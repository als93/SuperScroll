# Project Instructions

## General Guidelines
- Understand the existing implementation before making recommendations.
- Preserve the existing visual design and layout.
- Avoid unnecessary frameworks and dependencies.
- Prefer lightweight, native solutions.
- Do not assume functionality exists without verifying it.
- Refer to Human documentation when relevant.

## Code Reviews
- Inspect the entire relevant codebase.
- Identify bugs, performance issues, accessibility problems,
  security concerns, and potential improvements.
- Include specific file names and line numbers.
- Separate confirmed issues from optional recommendations.
- Prioritize findings by severity.
- Do not modify files during code reviews unless authorized.

## Development
- Keep changes consistent with the existing architecture.
- Avoid unnecessary redesigns.
- Explain how proposed features fit into the existing UI.
- Consider performance and compatibility.
- Do not modify anything in the Human directory.

## Git
- Do not commit or push changes without permission.
- Preserve existing functionality.
- Avoid overwriting unrelated work.
